An AI analyst that proposes, but never acts alone

Think of a security guard watching thousands of camera feeds. AI-SOC adds an assistant that reads each alert, looks up what it probably means, and suggests a response. Strict rules and a human decide what actually happens. Everything runs on your own machine, so no log data goes to the cloud.

The core idea in five steps

1. AI proposesThe local model reads the alert and suggests actions, such as “disable this account”. It can only write text.
2. Evidence supportsBefore answering, the system looks up MITRE ATT&CK notes and runbooks (RAG), so the answer rests on real knowledge.
3. Rules verifyThe policy engine checks fixed business rules, such as “never shut down a server”.
4. Safety constrainsThe safety engine scores each action from L0 (harmless) to L7 (catastrophic) and decides auto-run, ask a human, or block.
5. Humans approveRisky actions wait in the approval queue until an analyst clicks approve or reject.

The risk ladder in plain words

L0–L2: look and notify (send a message, search logs, check an IP reputation). Harmless.
L3–L4: small changes you can undo (create a record, tag an IOC, collect logs, block one IP). Auto-run.
L5–L6: disruptive (kill a process, isolate a host, disable an account). Needs a human.
L7: destructive (shut down a server, delete data). Never allowed.

How the safety code decides

Checks run strictest first, so a later permissive rule can never undo a block.
